# BEKHAN OS

Персональное пространство директора с подключённой CRM «Бронь Сервис».

[Рабочая CRM](https://bronservis51-bot.github.io/bekhan-os-demo/#/crm) ·
[Демонстрация](https://bronservis51-bot.github.io/bekhan-os-demo/#/crm/demo)

## Что подключено

CRM работает через существующий российский `api.bronservis.ru`: те же заявки,
UUID, учётные записи и серверные права, что в приложении франшизы. Лендинг
`bronservis.ru` продолжает отправлять анкету прежним маршрутом. Новая копия базы,
двойная отправка, webhook и новый сервер для этого не нужны.

Изменения статуса, заметки и корзины общие. Вход — существующая почта/пароль
менеджера. Чтение анонимам запрещено. На клиенте только публичный anon key.
Рабочие контакты не сохраняются в демо-хранилище и не входят в экспорт/ChatGPT.

Канбан: восемь комбинаций «Деньги / Помещение / Сейчас», «В работе», «Договор»,
«Отказ». Есть поиск, фильтр новых, переход к колонке, перетаскивание, короткая
форма, корзина и восстановление. «Перезвонить» и «Встреча» относятся к «В работе».
Договор не считается оплатой. Анкета и источник в карточке сохраняются сервером.

Фоновое обновление — раз в 30 секунд в открытой CRM и при возврате на вкладку.
Ошибки и время последнего чтения видны. Конфликт версии не затирает чужую работу;
повтор создания той же формы использует один UUID операции.

## Что остаётся примером

Финансы, обзор, сеть, контент, цели, задачи и тренировки работают с локальными
демоданными на 12 ноября 2026. Их серверное подключение — следующий отдельный
этап, а не результат подключения CRM. Старые изменения в браузере сохраняются
под прежним `bekhan-os-demo-v1`. Ручного переноса/сброса для обновления не нужно.

Пример CRM находится на отдельном маршруте. Демозаписи не импортируются в
рабочую базу. Сброс/экспорт примера не затрагивают реальные заявки и сессии.

## Архитектура

Модульный монолит без общих глобальных скриптов. Правило эволюционируемости,
адаптивности и изоляции закреплено в [AGENTS.md](AGENTS.md) и
[ADR-0001](docs/adr/0001-modular-monolith-and-shared-crm.md).

| Каталог | Ответственность |
| --- | --- |
| `src/app` | Композиция, маршруты и межмодульные read models |
| `src/modules/<feature>` | Экран, команды, состояние и правила одного направления |
| `src/integrations/bron-leads` | Заменяемый адаптер существующих Auth/RPC |
| `src/platform` | Модальный ввод, уведомления, локальное хранилище примера |
| `src/shared` | Общие элементы UI и чистые функции |
| `tests` | Контракты, границы данных, конфликты, повторы и совместимость |

Модули получают именованные порты, не импортируют внутренние файлы друг друга
и не вызывают SDK/HTTP напрямую. Зависимости проверяются автоматически. Следующий
источник подключается заменой адаптера конкретного модуля, не переписыванием
всего кабинета. Общий контракт всё равно требует проверки затронутых модулей.

## Разработка и публикация

Node 22+: `npm ci`, `npm run verify`. Для read-only проверки опубликованного
API — `npm run probe`. Сборка создаёт `dist/` и публичные `index.html`/`assets/`
в корне для существующего GitHub Pages main:/. SDK включён в собственный bundle.
Зависимости фиксированы lockfile. Секретов сервера в клиентской сборке нет.

Эксплуатация, безопасный откат и ограничения проверок:
[release-and-crm.md](docs/runbooks/release-and-crm.md).
